Components

Buttons

Three levels, used consistently: 1. Primary (.btn-submit/.btn-large) - filled, the one main action. 2. Secondary/cancel (.btn-cancel, paired with .btn-nav for sizing) - hollow, same border colour as the primary action next to it, so "the other choice" reads consistently everywhere a Cancel sits beside a Save. 3. Tertiary (.btn-text / .btn-text-danger) - text only, underlined, no fill or border. For a low-emphasis or destructive action kept deliberately away from a primary button it could be hit by mistake next to (e.g. a block editor's "Delete" moved into its own "Other actions" area below Cancel/Save).

Touch targets: every interactive element (buttons, icon buttons, steppers, slider thumbs) is at least 48x48px, even where the visible glyph is smaller - a slider thumb's hit area extends past its visible circle via an invisible ::before rather than being drawn larger.

.list-item-menu-btn - the 3-dot trigger for a list row's own options menu (ML-175): lighter grey-outline treatment than .btn-icon-edit's bold coloured border, sized for a compact row. Pair it with .dropdown-menu.metroBlk-tile-menu below for the menu itself - one shared floating menu per list (not one per row), repositioned via JS against whichever row's button was tapped.

Slider

Draggable track + thumb + fill, with an optional min/max scale caption. Static preview here (drag it live on the Metronome's target-speed or volume controls). Standard pattern: pair every slider with a numeric readout that's also a tap target - clicking/tapping it swaps in a real number input so a value can be typed directly, not just dragged or stepped to. Wire this with makeSliderReadoutEditable(displayElId, getValue, setValue, opts) in app.js rather than reimplementing it per control.

0100

Filter strip

.filter-strip - inline, 1-tap category filter (ML-176): a leading icon (decorative - "All" already covers "clear filters") with an active-count badge shown only when a subset is selected, plus a horizontal .filter-pill track. Each pill shows a live count and tints with that category's own colour when active (via the --filter-pill-accent custom property) rather than one flat colour for every pill, so the strip doubles as an at-a-glance legend. Used on the Detailed stats and Session history screens; reuse it for any future screen that needs a category filter.

tune3

Flow card

.flow-card - one bordered/rounded section for the Flow Details Hub (ML-179): a .flow-card-label + .flow-pill header, and neutral .flow-action-btn actions for "add another item" rather than a filled primary button. Recording rows embed a native <audio> control (or a YouTube iframe for a link) directly in the row rather than an "open in a new tab" button - play immediately without leaving the page. Delete uses .flow-delete-btn - a clickable circle like .list-item-menu-btn, just tinted red, rather than .btn-icon-delete's heavier solid-red-fill look (that stays reserved for deleting the whole flow).
