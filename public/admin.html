ML-199 - how long building a Flow by hand actually takes, so a redesigned Bars tab has something measured to be compared against rather than an impression that it feels quicker. Active time is wall clock with idle trimmed out: the stopwatch stops after 60s without input and whenever the page is hidden, so a session left open while the phone rang doesn't inflate the figure. Bars time is the part of that spent on the Bars tab (including the per-block inspector) - the bit the redesign is aimed at.

Per bar and per block are both shown because they answer different questions. One 16-bar block and sixteen 1-bar blocks are the same music but very different data entry: per block measures the cost of the card UI, per bar measures the cost per unit of actual music, which is the only fair way to compare flows of different lengths. Per bar is blank for edit sessions on purpose - an edit touches an unknown subset of the flow's bars, so any per-bar figure there would be arithmetic rather than a measurement.

Median leads, with min/max beside it. One interrupted run visibly moves a mean at this sample size. If min and max are miles apart, the median isn't describing anything stable yet - collect more runs before drawing a conclusion. Statistics cover completed, non-excluded sessions only; import-assisted (“Create from file”) runs are kept out of the headline and the breakdowns, and shown separately under Create vs edit.

Feedback

Submitted from the app's hamburger menu (ML-170). The form is a plain text box on purpose - category is set here, at triage, not by whoever sent it, so nothing stands between spotting a problem and writing it down. The screen, device and app version are captured automatically, which is what makes a one-line note still actionable a fortnight later.
